# VSRVES01 vendor firmware

The VSRVES01 build pulls one vendor artefact that is **not in any git
repo** — it lives as a ZIP download on the VSDSP forum
(account-walled).  Place the files in this directory before running
`image build` and `override-checkout.sh` will pick them up:

| File | Source | Used by |
|---|---|---|
| `vsrv_root_260511.zip` | https://www.vsdsp-forum.com/phpbb/viewtopic.php?t=3242 | unzipped into `/build/firmware/vsrv_root/` — provides `rvlbne.bin`, `startup.txt`, `rvparam.bin`, `shell.ap3`, `SYSR/*.dr3` (the DTB and kernel are built from source; the zip's `catboard.dtb`/`catboard.cpio` are unused) |
| `vsrv_root_260511.zip.sha256` | generated by you | hash pin checked before unzip (mandatory — `rvlbne.bin` embeds fixed `_ddrBlob` offsets that depend on the exact vendor payload layout in this zip) |

The Ethernet driver needs no download: it is in-tree via
`patches/0005`/`0006` (ported from the vendor's out-of-tree
`vlsi-lnx-drv`).

Generate the hash pin once after downloading:

```sh
cd boards/vsrves01/firmware/
sha256sum vsrv_root_260511.zip > vsrv_root_260511.zip.sha256
```

The vendor SDK release cadence is irregular — update the pinned
filename in `override-checkout.sh` when a newer revision is published.

**Redistribution:** the VLSI forum's terms are unclear; treat these
blobs as non-redistributable and require each user to download them
themselves.  Do not commit the binaries to the repo or include them in
any published image bundle.

## Manual SD card prep

The image we produce only carries the Linux side (`rvlbne.bin` +
`catboard.dtb` + `linux61.vri` + `image.sqfs` + `startup.txt` +
`SYSR/`).  The microSD card also needs VLSI's proprietary VSOS payload
(the VSDSP6 side), which is shipped pre-loaded on the CAT Board's
microSD card and documented at
https://www.vlsi.fi/en/support/evaluationboards/vsrves01catboard.html .
Easiest path: copy our FAT contents onto the vendor card overwriting
its `startup.txt` and `linux61.vri`, don't reformat.

`override-assemble.sh` copies the **vendor** `startup.txt` verbatim
and only sed-edits the `Term -a` and `ddrload` lines — the
`RvParam +mba:` MAC line is preserved from whatever the zip ships.
Check it against your CAT Board's sticker MAC and edit the line on the
card if they differ.
